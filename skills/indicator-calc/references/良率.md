# MES 良率（工单良率）口径

> 来源：DolphinScheduler `周报_WEEK_通用` → `周良率 指标-DWS层`（2026-08-11）。
> 落表：`dws_indicator_w`，`indicator_name = {flash_pn}_mes_week`，`indicator_value` 为 JSON `{pass, total, yield}`，维度见 `dimension_json`（`{item_capacity, month_number, month_week}`）。

## 业务定义
MES 生产良率 = 良品数 / 投入数，按 `flash_pn × product_type × project × process_flag(MT0/MT1/MT2) × item_capacity` 维度给出。
周粒度记录覆盖 **近 5 周 + 前 4 个月**（单表内多时间窗，用 `dimension_json.month_week` 区分周、`month_number` 区分月份）。

## 算法步骤
1. **源表**：`st_embed.dwd_mes_lot`
2. **过滤**：
   - `process in ('MT0','MT1','MT1R','MT2')`（process_flag：MT0→0，MT1→1，MT1R→1，MT2→2）
   - `bin_type = 'BIN1'`
   - 周窗：`dt >= date_add(trunc('${etl_dt}','week'), -4*7) and dt < date_add(trunc('${etl_dt}','week'), 7)`（前 5 周）
   - 月窗（eMMC 产品 `product_type like 'eMMC%'`）：`dt >= trunc(add_months('${etl_dt}',-5),'month') and dt < trunc('${etl_dt}','month')`（前 5 个月）
3. **分子/分母（关键，区分已完结与未完结工单）**：
   - **未完结工单**（无 MT1R 记录的工单，`flag=0`）：`pass = sum(bin_amount)`，`total = sum(work_amount)`
   - **已完结工单**（有 MT1R 记录，`flag=1`）：`pass = total_amount_week_view.pass_amount`，`total = total_amount_week_view.total_amount`，其中
     `total_amount_week_view = sum(work_amount), sum(bin_amount)` 按 `process='MT1' and bin_type='BIN1'` 聚合该工单
   - `MT1R` 行本身 `work_amount = 0`（避免重复计数投入）
4. **聚合维度**：`year_week_number, flash_pn, product_type, project, process_flag, item_capacity`
5. **良率**：`yield = pass_amount / total_amount`

## 直接查表 SQL（日/周已在表，直接查）
```sql
SELECT year_week_number, project, flash_pn, product_type, station, indicator_value
FROM st_embed.dws_indicator_w
WHERE indicator_name = '{flash_pn}_mes_week'
  AND year_week_number = '{周}'   -- 如 '2026年第32周'
  AND project = '{project}'
```
（`station` 列 = process 名：MT0/MT1/MT2；`indicator_value` 是 JSON，用 `get_json_object(indicator_value,'$.pass')` / `'$.total'` / `'$.yield'` 取值）

## 现算算法（表里没有的时间周期，如自定义日期段/月）
按算法步骤用 `sql_query` 现算，例如自定义日期段良率：
```sql
SELECT wo, flash_pn, project, product_type,
       SUM(work_amount) AS total_amount, SUM(bin_amount) AS pass_amount,
       SUM(bin_amount)/SUM(work_amount) AS yield
FROM st_embed.dwd_mes_lot
WHERE process = 'MT1' AND bin_type = 'BIN1'
  AND dt BETWEEN '{开始}' AND '{结束}'
GROUP BY wo, flash_pn, project, product_type
```
> 注意：表里没有单"日"良率指标，若要日良率需按上述现算；且已完结工单的 pass/total 口径（见第 3 步）在现算时也要按工单是否完结区分。

## 注意/陷阱
- **不是所有 product_type 都有月窗**：月窗只对 `product_type like 'eMMC%'`。
- **station 列 = process_flag 的 MT 名**，别和测试站位混淆。
- **yield 是 pass/total**，分子分母都来自 MES（非测试日志），不要用测试通过率替代。

# 完结良率（已完结工单，`{flash_pn}_finished_wo`）

> 来源：DolphinScheduler `周报_WEEK_通用` → `周已完结工单 指标-DWS层`（2026-08-11）。
> 落表：`dws_indicator_w`，`indicator_name = {flash_pn}_finished_wo`，`indicator_value` = JSON `{overall_output_ratio, total_cnt, pass_cnt}`，`dimension_json` = `{is_current_week, latest_dt, item_capacity}`。

## 业务定义
**只统计已完结工单**（`dim_base_wo_di.wo_status = 'completed'`）的良率口径，给出"整体出货/产出率"。与上面 `_mes_week`（含未完结工单）不同，这里用 MES 各 process 的投入/良品推算最终产出。

## 算法步骤
1. **源**：`dwd_mes_lot` JOIN `dim_base_project`（关联键 flash/item_control/pn/flash_pn/project，trim 后匹配）
2. **过滤**：`bin_type = 'BIN1'`，`factory <> 'J048'`（排除 J048 厂），`process in ('MT0','MT1','MT1R','MT2')`，
   `wo IN (SELECT wo FROM dim_base_wo_di WHERE wo_status='completed')` ← **只已完结工单**
3. **process_type**：MT0→0，MT1→1，MT1R→1，MT2→2
4. **各 process 聚合**（按 wo/lot/维度）：`pass = sum(pass_amount)`，`input = sum(work_amount)`，`fail = input - pass`
5. **工单级汇总**：`MT0_input/MT1_input/MT2_input`、`MT2_bin1`（MT2 的良品）、`MT1_fail/MT2_fail`
6. **最终产出 pass_cnt（overall_output）判定逻辑**：
   - 无 MT0 投入（null/0）时：
     - `MT2_input/MT1_input < 0.15` → pass = `MT1_input - MT1_fail - MT2_fail`
     - 否则 → pass = `MT2_bin1`
   - 有 MT0 投入时：
     - `MT2_input/MT0_input < 0.15` → pass = `MT1_input - MT1_fail - MT2_fail`
     - 否则 → pass = `MT2_bin1`
   - **yield（overall_output_ratio）** = 同一分支的 pass 除以 `MT1_input`（无 MT0）或 `MT0_input`（有 MT0）
   - 判定含义：MT2 投入占比很低（<15%，多为返测/未走到 MT2）时按"MT1 投入扣 fail"算，否则按 MT2 良品数算
7. **total_cnt** = `MT0_input > 0 ? MT0_input : MT1_input`（投产数）
8. **只保留最近 10 个已完结工单**：按 `(project, flash_pn, flash, item_capacity, item_control)` 分组 `ROW_NUMBER() OVER(ORDER BY latest_dt DESC)` 取 `rn <= 10`
9. **is_current_week**：`latest_dt` 是否落在当前周（`date_trunc('week')+1 ~ ${etl_dt}`）→ '1'/'0'

## 直接查表
```sql
SELECT wo, flash_pn, project, year_week_number, indicator_value,
       get_json_object(dimension_json,'$.is_current_week') AS is_current_week,
       get_json_object(dimension_json,'$.latest_dt') AS latest_dt
FROM st_embed.dws_indicator_w
WHERE indicator_name = '{flash_pn}_finished_wo'
  AND wo = '{wo}'
```
`indicator_value`：`$.overall_output_ratio`（良率）、`$.total_cnt`（投产）、`$.pass_cnt`（产出）。

## 注意/陷阱
- **与 `_mes_week` 的区别**：`_mes_week` 含未完结工单（process MT1/MT1R 全量），`_finished_wo` 只看 `wo_status='completed'` 的工单，产出是推算值（15% 判定）。
- **15% 判定是核心**：MT2 投入占比 <15% 时走"MT1 扣 fail"，否则用 MT2 良品。别直接拿 MT2_bin1 当产出。
- `factory <> 'J048'` 是硬过滤；`dim_base_project` 里 flash_pn 若不存在则不参与。
- 表里只保留**每个维度最近 10 个**已完结工单，查老工单可能查不到。
